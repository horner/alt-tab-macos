# Snapshot Markdown viewer

The native AppKit window loads the checked-in `dist/viewer.html` resource, replacing its single `__SNAPSHOT_DATA__` token with JSON containing `markdown` and `images`. The `images` dictionary maps a Markdown image destination, decoded once, to an absolute local file URL verified by native code. Native code escapes `<`, `>`, `&`, U+2028, and U+2029 in JSON before insertion into `script#snapshot-data`. No document content is evaluated as JavaScript.

Markdown uses markdown-it with raw HTML and automatic URL linking disabled. Explicit HTTP and HTTPS links remain clickable for the native navigation delegate to open in the browser. Other links stay readable as text. An image renders only when its decoded destination is an own property of the native-approved map and its mapped value is an absolute `file:///` URL. Unapproved images and failed image loads show a readable placeholder.

The viewer uses system fonts, selectable text, responsive screenshots, and light/dark styles. A screenshot is a keyboard-accessible button. Clicking it or pressing Return/Space opens a scrollable view at the image's original size. Escape or Close dismisses the overlay and returns focus to its source button. Tab remains in the image dialog while it is open.

After rendering, the root HTML element has `data-viewer-state="ready"` and the viewer posts `{type: "ready"}` to `window.webkit.messageHandlers.snapshotViewer`. On a render failure the state becomes `error`, readable fallback text appears, and it posts `{type: "error", message: string}`. Native code can check this state after navigation to detect failures before JavaScript starts. Native appearance updates set `data-theme="light"` or `data-theme="dark"`; otherwise the viewer follows `prefers-color-scheme` where available.

All CSS, JavaScript, fonts, and dependencies are local or system-provided. The generated document's content security policy allows only the SHA-256 hash of its exact bundled script, inline styles, and file images. Connections, remote resources, forms, and base URL changes are disabled. Native code separately restricts file access to the snapshot archive and rejects page navigation.

`npm run viewer:build` regenerates `dist/viewer.html`, third-party license notices, and a SHA-256 manifest of sources and generated resources. `npm run viewer:check` type-checks, detects stale generated resources, and runs injection, link, image, error, and compatibility regressions. The native build invokes `scripts/check-snapshot-viewer.sh`, which checks the source file set and manifest using system tools. Generated output is deterministic and checked in, so normal Swift app builds do not need Node or network access.

The build targets Safari 10 (the WebKit generation on macOS 10.12). Esbuild bundles the code at ES2015, TypeScript lowers block scoping and iteration to ES5 because esbuild cannot lower Safari 10's block-scoping bugs, and a final esbuild pass verifies Safari 10 syntax. The bundled parser uses ES2015 Map, Set, typed arrays, and string APIs available in that WebKit generation; it does not need newer runtime polyfills. Bundle execution tests remove common newer builtin APIs to catch accidental dependency upgrades. A modern macOS smoke test does not replace testing on macOS 10.12 itself.
